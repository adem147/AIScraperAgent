2. CE QUE VOUS AVEZ FAIT (Détail des fonctionnalités à expliquer)
================================================================================

A. L'Intégration du LLM NVIDIA (LLM/nvidia_client.py)
   - Utilisation du modèle 'meta/llama-3.1-8b-instruct' via l'API NVIDIA Build.
   - Temps de réponse ultra-rapide (quelques centaines de millisecondes).
   - Forçage du format JSON strict avec système de réparation automatique des 
     réponses pour garantir qu'aucune erreur de parsing ne plante l'application.

B. Le Module d'Extraction NLP Multilingue (LLM/nlp_extractor.py)
   - Capable d'ingérer du texte brut non structuré (copier-coller de cahier des 
     charges, extrait PDF, page web).
   - Traitement multilingue complet : Français (FR), Anglais (EN), Arabe (AR).
   - Extraction structurée des entités :
     * Objet / Titre du projet
     * Organisme acheteur (Ministère, Banque Mondiale, INT, etc.)
     * Dates clés (Publication, Date limite de soumission, Ouverture des plis)
     * Budget estimé & Devise (TND, EUR, USD...)
     * Lots détaillés (Numéro de lot, intitulé, budget spécifique)
     * Critères d'éligibilité et de qualification
     * Documents administratifs et techniques exigés (Caution provisoire, 
       quitus fiscal, attestation CNSS, offres technique/financière).

C. Le Normalisateur de JSON Hétérogène (LLM/json_transformer.py)
   - Résout le problème des portails multiples : chaque site web utilise des 
     noms de variables différents ('bid_description', 'project_name', 'descr', 
     'ddv', 'subm_date', etc.).
   - Le transformateur prend n'importe quel format JSON brut et le convertit 
     instantanément dans le schéma unifié Pydantic 'ProcurementNotice'.

D. Le Moteur de Scoring et Calibration de Pertinence (LLM/relevance_scorer.py)
   - Définit le profil d'expertise du CERT : Intelligence Artificielle, 
     Cybersécurité / SOC, Télécommunications / 5G / IoT, Cloud & DevOps, 
     Ingénierie Logicielle.
   - Système hybride de calcul de score (0.0 à 1.0) :
     * 40% par similarité sémantique vectorielle dense (embeddings).
     * 60% par raisonnement contextuel du LLM avec justification écrite.
   - Calibration stricte avec seuil >= 70% :
     * Si score >= 0.70 -> is_relevant = True (Opportunité retenue).
     * Si score < 0.70 -> is_relevant = False (Rejet des projets hors domaine, 
       ex: BTP, génie civil, routes, agriculture).

E. La Synthèse et l'Analyse de Faisabilité (LLM/feasibility_analyser.py)
   - Synthèse de l'opportunité : Résumé exécutif clair en français pour les 
     décideurs.
   - Analyse de faisabilité préliminaire :
     * Adéquation technique avec les ressources du CERT.
     * Compétences et profils d'ingénieurs indispensables.
     * Risques et contraintes identifiés (délais serrés, cautionnement, pénalités).
     * Recommandation finale : 'GO', 'NO-GO' ou 'A_ETUDIER_AVEC_PARTENAIRE'.

F. Validation & Tests Automatisés (tests/test_phase2_nlp.py)
   - Création d'un corpus d'évaluation annoté multilingue (tests/annotated_corpus.json).
   - 8 tests automatisés unitaires et d'intégration validant 100% de la chaîne.

4. COMMENT TOUT FONCTIONNE SOUS LE CAPOT (Architecture technique)
================================================================================

Le flux d'exécution complet se déroule en 5 étapes successives :

[ ENTRÉE BRUTE ] 
     |
     +--> (A) Texte brut (FR / EN / AR)  --> LLM/nlp_extractor.py
     +--> (B) JSON hétérogène / Scraper   --> LLM/json_transformer.py
     |
[ SCHEMA UNIFIÉ ] 
     |  (ProcurementNotice : Objet, Organisme, Dates, Budget, Lots, Critères, Docs)
     v
[ SCORING DE PERTINENCE ] (LLM/relevance_scorer.py)
     |  - Embeddings MiniLM (40%) + Raisonnement LLM (60%)
     |  - Seuil >= 70% -> is_relevant: True / False + Justification
     v
[ ANALYSE DE FAISABILITE ] (LLM/feasibility_analyser.py)
     |  - Synthèse exécutive
     |  - Adéquation, Compétences requises, Risques
     |  - Décision stratégique : GO / NO-GO / PARTENAIRE
     v
[ PERSISTANCE & EXPLOITATION ]
     +--> Base relationnelle SQLite (CERT.db via SQLAlchemy)
     +--> Base vectorielle Qdrant (Recherche sémantique rapide)
     +--> Endpoints REST FastAPI (/api/extract, /api/transform-json)

6. FOIRE AUX QUESTIONS TECHNIQUES
================================================================================

Q : Quel LLM utilise-t-on et pourquoi ?
R : Nous utilisons 'meta/llama-3.1-8b-instruct' hébergé sur l'infrastructure 
    NVIDIA Build API. Il a été choisi pour sa très faible latence (< 300 ms), 
    son respect parfait des structures JSON et son excellent support du 
    français, de l'anglais et de l'arabe.

Q : Où sont stockées les données extraites ?
R : Les données sont stockées dans la base SQLite locale 'CERT.db' avec les 
    colonnes structurées (lots, critères, budget, analyse de faisabilité), et 
    les descriptions sont vectorisées dans Qdrant pour la recherche sémantique.

Q : Comment le seuil de 70% a-t-il été calibré ?
R : Le scorer combine un vecteur d'alignement thématique avec les 5 piliers du 
    CERT (IA, Cyber, Télécom, Cloud, Logiciel) et une évaluation explicite par 
    le LLM. Les opportunités IT/Télécom obtiennent systématiquement un score 
    entre 75% et 95%, tandis que les secteurs non pertinents (BTP, santé 
    matérielle, agriculture) obtiennent moins de 30%.
