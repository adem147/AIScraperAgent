2. WHAT YOU BUILT (Detailed Breakdown of All Features)
================================================================================

A. Fast NVIDIA LLM Client (LLM/nvidia_client.py)
   - Powered by 'meta/llama-3.1-8b-instruct' via NVIDIA Build API.
   - Ultra-fast response times (~100–300 ms).
   - Strict JSON mode enforcement with automated error-recovery and markdown 
     stripping to ensure parsing never crashes the system.

B. Multilingual NLP Extraction Engine (LLM/nlp_extractor.py)
   - Ingests raw unstructured text (copied tender specifications, PDF extracts, 
     scraped HTML).
   - Full multilingual support: French (FR), English (EN), and Arabic (AR).
   - Extracts structured entities:
     * Objet: Full title / subject of the tender or AMI
     * Organisme: Issuing buyer, ministry, or international agency
     * Dates: Publication date, submission deadline, opening date
     * Budget: Numeric amount, currency (TND, EUR, USD), estimation status
     * Lots: Number of lots, titles, technical scopes, specific lot budgets
     * Critères: Mandatory qualification and evaluation criteria
     * Documents requis: Required administrative and technical documents 
       (e.g., bid security bond / caution provisoire, tax clearance certificate, 
       technical and financial bids).

C. Universal JSON Schema Transformer (LLM/json_transformer.py)
   - Solves the multi-portal problem: different websites use conflicting key 
     names ('bid_description', 'project_name', 'descr', 'buyer', 'ddv', etc.).
   - Automatically maps any arbitrary JSON into our unified Pydantic 
     'ProcurementNotice' model.

D. Relevance Scoring & Calibration Engine (LLM/relevance_scorer.py)
   - Models CERT's strategic domain profile: Artificial Intelligence / ML, 
     Cybersecurity / SOC, Telecom / 5G / IoT, Cloud & DevOps, Software Engineering.
   - Hybrid scoring formula (0.0 to 1.0):
     * 40% dense semantic embeddings (SentenceTransformer all-MiniLM-L6-v2)
     * 60% LLM contextual reasoning with written justification
   - 70% Threshold Rule:
     * If Score >= 0.70 -> is_relevant = True (Retained as priority opportunity)
     * If Score < 0.70  -> is_relevant = False (Automatic rejection of unrelated 
       fields like road construction, civil engineering, agriculture).

E. Opportunity Synthesis & Feasibility Analysis (LLM/feasibility_analyser.py)
   - Executive Summary (synthèse_opportunite): Concise overview for decision-makers.
   - Preliminary Feasibility Analysis (analyse_faisabilite):
     * Technical capability alignment with CERT internal teams
     * Key engineering profiles required to bid (e.g. Lead Architect, Data Scientist)
     * Identified operational/contractual risks (tight deadlines, bank bonds)
     * Strategic recommendation: 'GO', 'NO-GO', or 'A_ETUDIER_AVEC_PARTENAIRE'.

F. Validation & Automated Test Suite (tests/test_phase2_nlp.py)
   - Annotated multilingual test corpus (tests/annotated_corpus.json).
   - 8 automated unit & integration tests validating 100% of the pipeline.

4. HOW EVERYTHING WORKS UNDER THE HOOD (Technical Architecture)
================================================================================

The end-to-end data pipeline executes in 5 sequential stages:

[ RAW INPUT ] 
     |
     +--> (A) Raw Text in FR / EN / AR   --> LLM/nlp_extractor.py
     +--> (B) Messy / Heterogeneous JSON --> LLM/json_transformer.py
     |
[ UNIFIED SCHEMA ] 
     |  (ProcurementNotice: Objet, Organisme, Dates, Budget, Lots, Criteria, Docs)
     v
[ RELEVANCE SCORING ] (LLM/relevance_scorer.py)
     |  - MiniLM Dense Embeddings (40%) + LLM Reasoning (60%)
     |  - Threshold >= 70% -> is_relevant: True / False + Rationale
     v
[ FEASIBILITY & SYNTHESIS ] (LLM/feasibility_analyser.py)
     |  - Executive Summary
     |  - Technical match, Required competencies, Identified risks
     |  - Decision: GO / NO-GO / CONSIDER WITH PARTNER
     v
[ PERSISTENCE & REST EXPLOITATION ]
     +--> SQLite Relational Storage (CERT.db via SQLAlchemy)
     +--> Qdrant Vector Store (Fast semantic similarity search)
     +--> FastAPI REST Endpoints (/api/extract, /api/transform-json)

6. TECHNICAL FAQ (Answers to Tough Questions)
================================================================================

Q: Which LLM are we using and why?
A: We are using 'meta/llama-3.1-8b-instruct' hosted on NVIDIA Build API. It was 
   chosen for its low latency (< 300 ms), high instruction-following precision 
   for strict JSON formatting, and strong multilingual capabilities (FR/EN/AR).

Q: Where is the extracted data stored?
A: Extracted structured data (lots, criteria, budget, feasibility, dates) is 
   stored in local SQLite ('CERT.db') via SQLAlchemy, and text descriptions are 
   embedded into Qdrant for semantic similarity queries.

Q: How is the 70% relevance threshold calibrated?
A: The scorer combines semantic cosine similarity against CERT's 5 core pillars 
   (AI, Cyber, Telecom, Cloud, Software) with an LLM evaluation. Relevant IT/Telecom 
   tenders score between 75% and 95%, while irrelevant tenders (civil engineering, 
   medical equipment, agriculture) score below 30%.
